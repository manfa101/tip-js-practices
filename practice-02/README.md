## 4. Модель данных, проверки и функции

Задача: `{ id, title, completed, priority }`.

- `id` — положительное безопасное целое число, уникально в списке.
- `title` — строка; после `trim()` длина от 1 до 100. Хранится без краевых пробелов, внутренние пробелы сохраняются.
- `completed` — boolean; при создании `false`.
- `priority` — `"low"`, `"medium"` или `"high"`; по умолчанию `"medium"`.

**Файлы:**

| Файл | Ответственность |
|---|---|
| `src/task-service.js` | Чистые функции: создание, поиск, фильтрация, сводка, добавление, смена статуса, переименование, удаление |
| `src/data.js` | Общий набор `demoTasks` и индивидуальный набор `variantTasks` |
| `src/main.js` | Демонстрационный сценарий и вывод (без вычислений) |
| `examples/functions-and-references.js` | Шесть экспериментов |
| `checks.js` | Проверки (35 общих и три собственные) |

**Результаты функций.** `createTask` и операции со списком возвращают `{ ok: true, task }` или `{ ok: true, tasks }` при успехе и `{ ok: false, error }` при ошибке. Исходные массивы и объекты не изменяются. Добавление использует spread, изменение — `map` с копированием объекта, удаление — `filter`.

**Почему id не равен индексу.** Индекс меняется при удалении и добавлении записей, а `id` закреплён за задачей. Поэтому задача ищется через `find(task => task.id === id)`, а не по позиции в массиве.

**Почему `getTaskStats` возвращает число, а не строку.** Число можно использовать в вычислениях и сравнениях. Округление нужно только для вывода, поэтому `toFixed(1)` вызывается в `main.js`, а в сводке `progress` остаётся неокруглённым числом.

**Какие объекты копируются.** При изменении статуса или названия создаётся новый массив и новый объект только изменяемой задачи. Остальные записи переиспользуются: ссылки на них те же. Исходный массив и объект изменяемой задачи остаются прежними.
