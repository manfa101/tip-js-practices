## Результат

Реализованы чистые предметные функции (`src/domain/task-service.js`), компоненты `TaskStats`, `TaskFilters`, `TaskList`, `TaskItem`, `TaskForm` и владелец состояния `App`. Приложение создаёт и редактирует задачи через управляемую форму с проверкой ввода, переключает статус, удаляет с подтверждением, фильтрует по четырём условиям и показывает статистику полного набора. Данные хранятся только в памяти: обновление страницы восстанавливает исходный набор из 12 задач и начальные фильтры варианта. HTTP-запросы, `useEffect` и `localStorage` не используются.

## Компоненты и состояние

| Состояние | Владелец | Назначение |
|---|---|---|
| `tasks` | `App` | Полный массив задач (копия исходного набора при старте) |
| `filters` | `App` | Четыре значения фильтров (`q`, `completed`, `priority`, `categoryId`) |
| `editingId` | `App` | id редактируемой задачи или `null` |
| `notice` | `App` | Текст результата действия в области `role="status"` |
| `draft`, `errors`, `saveError` | `TaskForm` | Черновик формы, ошибки полей и ошибка сохранения |

Данные передаются вниз через props: `App` → `TaskStats` (`stats`), `TaskFilters` (`filters`, `categories`, `onChange`), `TaskForm` (`categories`, `initialTask`, `onSave`, `onCancel`), `TaskList` (`tasks`, `categories`, обратные вызовы) → `TaskItem` (`task`, `categoryName`, `onToggle`, `onEdit`, `onDelete`). Действия поднимаются наверх вызовами функций: карточка вызывает, например, `onToggle(task.id)`, а `App` обновляет общий массив.

Производные данные не хранятся в состоянии, а вычисляются при каждом рендере: `visibleTasks = selectTasks(tasks, filters)`, `stats = getTaskStats(tasks)`, `editingTask = tasks.find(...)`. Иначе их пришлось бы синхронизировать после каждого действия.

**Неизменяемые обновления.** Все операции возвращают новые массивы и объекты (`map`, `filter`, spread); исходные данные не мутируются. Обновление зависит от предыдущего массива, поэтому используется функциональная форма `setTasks(previous => ...)`. Подтверждение удаления и вычисление id выполняются вне функции обновления: в `StrictMode` она может вызываться дважды. Новый id — максимум **полного** массива плюс 1 (для пустого — 1), вычисляется внутри чистого обновления.

**Ключи.** Карточка получает `key={task.id}`: стабильный id связывает элемент с данными при удалении и перестановке, индекс для этого не подходит.

**Сброс формы.** `useState(initialTask)` читает начальное значение только при монтировании, поэтому форма рендерится как `<TaskForm key={editingId ?? 'new'} ... />`: при смене редактируемой задачи ключ меняется, и черновик создаётся заново. После успешного создания форма очищает черновик сама; после редактирования `App` сбрасывает `editingId` в `null`, и форма возвращается в режим создания. `onSave` синхронный: возвращает `true` при принятом изменении и `false` при отказе (задача уже удалена); при `false` показывается `role="alert"`, а ввод сохраняется.

## Контрольные вопросы

1. **Чем JSX отличается от строки HTML?** JSX — синтаксис JavaScript, описывающий дерево элементов React (используются `className`, `htmlFor`, выражения в `{}`), а не текст, который разбирается как HTML; значения в `{}` вставляются как текст.
2. **Чем props отличаются от состояния?** Props передаёт родитель, дочерний компонент их не меняет. Состояние принадлежит самому компоненту и изменяется его функцией обновления.
3. **Почему изменение обычной переменной не заменяет `useState`?** Обычная переменная не сохраняется между вызовами компонента и не запрашивает повторный рендер.
4. **Когда требуется функциональная форма обновления состояния?** Когда новое значение зависит от предыдущего (`setTasks(previous => ...)`), чтобы не опираться на устаревшее значение.
5. **Почему нельзя менять объект задачи внутри поверхностной копии массива?** Копия массива содержит те же объекты, поэтому изменение объекта изменит и исходное состояние. Для изменения записи создаётся новый объект.
6. **Для чего списку стабильный `key` и почему индекс не подходит?** `key` связывает элемент с данными при удалении и перестановке. Индекс меняется при изменении списка, поэтому состояние и DOM могли бы перепутаться.
7. **Почему видимая выборка и статистика не хранятся в отдельных состояниях?** Их можно вычислить из `tasks` и `filters`; отдельные состояния пришлось бы синхронизировать после каждого действия.
8. **Как дочерний компонент сообщает родителю о действии?** Вызывает функцию, переданную в props (`onToggle(task.id)`), а родитель изменяет общее состояние.
9. **Что делает поле управляемым?** Его значение берётся из состояния (`value`), а изменение обрабатывается `onChange`.
10. **Почему `categoryId` из `select` требует преобразования?** Значение элемента формы — строка. Перед использованием её преобразуют в число и проверяют (`'2x'` не принимается).
11. **Как меняется состояние формы при изменении её ключа?** React размонтирует форму и создаёт новую: локальное состояние формы сбрасывается и заполняется заново.
12. **Почему подтверждение удаления не помещается внутрь функции обновления?** Эта функция должна быть чистой и в `StrictMode` может вызываться повторно; диалог — побочное действие и выполняется до `setTasks`.
13. **Как отличить отсутствие задач от отсутствия совпадений фильтра?** По статистике полного набора: при пустом массиве «Всего» равно 0, а при отсутствии совпадений «Всего» больше 0, но «Найдено: 0».
14. **Что проверяет `npm test` и чего он не проверяет?** Проверяет предметные функции (валидация, фильтры, статистика, операции, отсутствие мутаций). Не проверяет компоненты, события, доступность и вид интерфейса.
15. **Какие части приложения потребуется изменить для подключения API в ПР8?** `onSave` и обработчики действий станут асинхронными, данные начнут загружаться запросами, потребуются состояния загрузки и ошибки, и тесты на Promise.

## Вывод

Приложение собрано из компонентов React с единым владельцем состояния App: данные передаются через props, действия поднимаются вызовами функций. Список и статистика вычисляются при рендере, состояние обновляется неизменяемо, у карточек стабильный key, форма сбрасывается при смене редактируемой задачи через key. Предметные функции вынесены отдельно и проверены тестами без React (28 из 28).
